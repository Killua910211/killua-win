# 决策：学习空间按科目组织，一门科目一个分区

- 状态：已接受
- 日期：2026-09-08（2026-09-09 修订：AI 编程工作流已撤下，规则不变）

## 决定

`/learning` 是科目的集合，不是某一门科目的首页。

- 每门已铺开的科目在学习页上**各占一个顶层分区**，分区内部再分块；科目之间没有主次。
- 分区顺序固定为：`01` 首屏 → 每门科目各一节 → 学习方法排最后。加一门科目，学习方法自己往后顺延。
- 科目清单的唯一来源是 `app/learning/subjects.ts`；分区编号、深浅面交替、分区导航和「之后的科目（规划中）」列表全部从这一个数组推出。
- 科目自己的编号（科目 01 哲学）和分区编号是两套：前者写在分区正文的 eyebrow 上，后者是这一页的第几节。
- 每门科目的完整内容放在自己的路由下（哲学是 `/learning/philosophy`），学习页上的分区是入口加要点。

## 原因

哲学是第一门铺开的科目，「按问题」「按传统」一度各占一个顶层分区，学习页的结构等于哲学的结构。这样一来，加第二门科目时版面会把先来的写成主线、后来的写成附录——而科目之间其实平级。

把「一门科目 = 一个分区」定成规则后，平级关系在版面上直接可见，加科目也只是接着往下排一节，不用每次重新决定整页的层级。

## 证据

- `app/learning/subjects.ts`：`Subject` 类型与 4 条数据（哲学已铺开，心理学、历史、科学规划中）；`subjectSectionNumber()`、`methodSectionNumber`、`subjectSectionTone()`、`subjectNumber()` 都由这个数组算出。
- `app/learning/page.tsx`：`01` 首屏、`02` 哲学、`03` 学习方法；科目分区由 `subjectSectionProps()` 生成外壳。
- `app/globals.css`：`.learning-subject-section` 是科目分区共用的外壳，`--a` / `--b` 两种面交替；`.learning-block-heading` 是分区内部分块的小标题。

## 后果

- 加一门科目的顺序是：往 `subjects.ts` 加数据 → 建自己的路由 → 在学习页加一个 `.learning-subject-section` 分区。分区编号、导航和规划列表不用手改。
- 哲学的「按问题」「按传统」是分区内部的两块，标题层级为 `h3`；`CoreQuestionGroups` 因此支持 `headingLevel`，相关 CSS 用 `:is(h3, h4)` 同时匹配两种用法，好让哲学总览页继续用 `h3`。
- 学习方法固定用最深的一层（`var(--black)`）收尾，科目数量是奇是偶，它都不会和上一节撞成同一个面。
- 科目分区展示的是「这门科目有什么」，不是「你学到哪了」。学习空间到目前为止没有任何进度状态，新增科目不要引入。
- 这套结构本身与具体科目无关：2026-09-09 撤下 AI 编程工作流后，`subjects.ts` 少一条、学习方法从 `04` 回到 `03`，其余不动。
