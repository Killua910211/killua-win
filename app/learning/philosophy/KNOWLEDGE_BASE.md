# 哲学知识库建设准则（执行必读）

本文件只约束 `app/learning/philosophy` 的知识建设；它不是全仓库开发规范。

## 目标与范围

建设面向中文读者、可理解、可追溯、相互关联、可持续修订的哲学知识系统。以问题连接概念、立场、论证、人物、著作与历史语境；不把名称相近的跨传统概念直接等同。

- **核心**：问题型与概念型条目，以及支撑它们的传统／历史线索。
- **扩展**：原典精读、版本比较、专门论争、跨传统的可比性研究。
- **暂不纳入**：未经核验的“学界共识”、用几句断语概括整种传统、把当代政策事实当作哲学结论。

## 条目标准

问题型、概念型核心条目必须说明：问题为何产生；定义与边界；主要立场及支持理由；有力反对及回应；易混概念；具体例子；来源与阅读路径。历史条目必须说明时段和材料的边界、问题与文本如何进入该语境、后世分类的限度；不能把历史分期当作自然事实。

按条目性质调整结构，不能用人物名单、目录、占位段落或重复模板替代正文。

## 来源与标记

先读来源，再写正文。每项重要论断必须在“来源与核验记录”中对应具体著作、章节或网页小节。正文必须标明它是：原文、概括、解释性重构、原创例子或争议性判断。不得虚构引文、页码、著作、影响关系或共识；未实际核对的内容标为待核验。

## 工作与审查

每轮先审查现有材料，优先修正错误和理解断层。每篇保留范围、状态、来源核验、自审结果、相邻条目影响与下一步。独立审查可用时另行标注；未做独立审查时，只能标为自审。关键问题未解决的内容必须保留草稿状态。


## 数据架构（2026-09-11 起）

新增哲学内容应当通过加数据完成，而不是每加一个主题就重写一套 UI；同时不要为将来可能出现的学科建一套通用 CMS。当前分层：

| 文件 | 负责 | 加内容时改哪里 |
| --- | --- | --- |
| `data.json` | 节点树、摘要、问题、立场（含反对与回应）、传统与历史线索；导航页的读者导语与建议阅读顺序（`guidance`） | 新主题先进这里 |
| `content-ledger.ts` / `remaining-content-ledgers.ts` | 研究层：具体入口、默认已知、问题起点、定义与边界、有力反对及回应、易混、回到问题、来源与核验记录、审查记录 | 每个条目一份 |
| `study-guides.ts` / `remaining-study-guides.ts` | 精读层：拆解、按立场名索引的论证路径、人物如何改写问题、原典阅读路径 | 核心问题才需要 |
| `relations.ts` | 节点之间的语义关系与横向链条 | 建立连接时 |
| `concepts.ts` | 跨条目复用的概念定义（全站唯一版本） | 概念跨两页以上时 |
| `argument-maps.ts` | 论证地图：共同主干 → 分歧点 → 各立场的反对、回应与理论代价 | 只给有明确论证骨架的条目 |
| `thought-experiments.ts` | 改变变量式思想实验 | 需要逼出隐含原则时 |
| `comparisons.ts` | 跨传统可比问题 | 两个传统能就同一问题对话时 |
| `learning-path.ts` | 推荐基础学习路径 | 路线调整时 |

## 教学结构（2026-09-19 起）

一个条目页从上到下是固定的：**本页范围 → 读这一页之前 → 问题为何会出现（先具体入口、后概括）→ 先把问题拆开（概念解释）→ 定义与边界 → 论证地图／主要立场 → 有力反对及回应 → 案例推演 → 思想实验 → 回到问题 → 带着问题继续读 → 继续学习 → 折叠的研究层**。这个顺序是一条教学承诺，写在哲学总览上给读者看，改动时两处要同改。

三个字段承担新的分工，定义与红线见 `content-ledger.ts` 顶部的类型注释：

- **`entry: { scene, turn }`（具体入口）** —— 一个不含术语、不下判断的具体情形，再由它逼出本页的问题。它排在概括之前。写它的理由：`data.json` 的 `example` 在有精读层或思想实验的页面上根本不渲染，23 个核心问题页的例子从来没有显示过。
- **`assumed: { point, recap, nodeId? }[]`（本页默认你已经知道的）** —— 关系层的 `prerequisite` 说的是整页依赖整页，全库只有十二条，而且同一对节点之间只能有一条边；覆盖不到「本页要用、要到别处才展开」的那些具体区分。每条必须附一句**不跳转也够用**的回顾——写不出这句，就说明这一条其实不必前置，应当在正文里就地解释。
- **`takeaway: { question, split, settled, open }`（回到问题）** —— `split` 必须**先用本页立场名收一遍**再讲分歧落在哪一步。本轮复审抓到五页的 `split` 换了另一套分类，读者刚读完的立场在总结里消失（「修养取向」「共和」「德治」几条因此被系统性地排除在页面总结之外）。

导航页（总览、两个目录分组、六个问题域、五条传统导航）没有研究层，改用 `PhilosophyNode.guidance`：`lead` 说清这一组问题在追问什么、为什么放在一起；`order` 给下一级一个建议顺序并逐条写明理由。**展示顺序一律走 `orderedChildren()`**——目录页、条目页的下一层、学习空间首页、知识地图、页底分页器都用它，有一处不走就会出现「这一域第 02 篇」与「点下一页却跳到另一篇」的矛盾。

几条硬约束：

- **论证路径按立场名索引，不按数组下标。** `positionArguments` 的键必须与 `data.json` 里该立场的 `name` 完全一致，`study-guides.ts` 末尾有构建期校验。旧的下标对齐结构曾把当代福祉理论的论证挂到「修身与解脱」（儒家与佛教，现已改名「修养取向」）标题下，把内部主义挂到「经验主义」下。
- **关系必须有语义和理由。** 七种关系各自要求回答一个具体问题（见 `relations.ts` 的 `mustAnswer`）。刻意没有「相关」兜底项——说不出理由的边不要连。父子边不进关系层。
- **概念定义只有一份。** 跨条目复用的概念进 `concepts.ts`，各页只补一句「在本页」的角度。正文里的行内注解写 `[[concept-id|显示文本]]`，id 不存在会在构建期抛错；同一页同一个概念只标第一次出现。
- **思想实验不是心理测试。** `thought-experiments.ts` 有一条机械防线会拦下收尾里的立场标签。正确的收尾是继续提问。
- **跨传统比较从可比问题开始，不从「哪个传统相当于哪一派」开始。** `comparisons.ts` 的 `caution` 是必填字段。刻意不用表格：表格的每一行都在暗示同一个格子对应同一个东西。
- **零 JS。** 展开交互全部用原生 `<details>`；不要为知识图谱引入 Graph / Canvas 引擎，不要把学习页变成大型 Client Component。

## 来源核验（2026-09-11 起收紧）

`LedgerSource.checked` 是 `'verified' | 'pending' | 'broken'` 三态，页面显示的就是这个值。此前它的类型是字面量 `true`，「待核验」在类型上无法表达，渲染层又把「已核验」硬编码在 JSX 里——结果标着「已核验」的来源里查出了 9 条失效链接、两处凭空写出的章节号和一个已不存在的域名。

- 写 `'verified'` 的前提是：本轮实际打开过那个页面，标题相符，locator 里的章节**真的存在**，supports 声称的论断**真的由该页支持**。同时写 `checkedOn`。
- 做不到就是 `'pending'`，并把 locator 收窄到能确认的范围。链接失效且找不到替代写 `'broken'`。
- locator 不接受「相关章节」「相关段落」「各节」「全文」这类无法定位的表述。
- 禁止：编造页码、章节号、著作、引文、历史影响关系、学界共识；禁止根据搜索摘要声称读过论文。

已知的结构性缺口（写在 `coverage.ts` 里，不折算成完成度）：来源高度集中在英文 SEP；论及儒家、道家、正理、吠檀多、伊斯兰与非洲哲学的条目大多只有英文综述，中文原典尚未进入核验记录。

## 每轮工作的顺序

先审查现有材料，再动手。整改清单与跨页结论记在 `CONTENT_GAP_REVIEW.md`，按 Critical / High / Medium / Low 排，优先级依据是：事实错误 > 哲学解释错误 > 容易造成误解 > 核心知识链断裂 > 阅读体验 > 次级内容扩展。

审查必须主动找问题——最薄弱的论证、最容易误导的表达、最缺依据的判断、最像 AI 套话的段落、最明显的知识断层、最弱的反方、最生硬的跨传统类比、最没有必要的段落。不输出「内容已经非常全面」这类结论。

单轮工作量大、需要逐页留痕时，另起一份该轮的记录文件（2026-09-19 教学重构轮的完整记录——中文资料对照、逐页清单、自我复审、未完成事项——在 `TEACHING_REBUILD.md`），`CONTENT_GAP_REVIEW.md` 只留跨页结论并指过去。

不以节点数量为 KPI。只有当审查明确发现某个缺失节点造成知识链断裂时才新增；发现的连接断裂属于关系层，不靠加节点解决。
